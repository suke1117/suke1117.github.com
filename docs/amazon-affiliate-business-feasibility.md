# 案3「せどり事業者向けデータ提供」成立判定レポート

調査日: 2026-08-24

## 結論

**案3は Amazon 公式 API 上では成立しない（NO-GO）。**

規約・技術・事業継続性の3レイヤすべてに独立した致命傷がある。どれか1つでも回避不能で、
3つ同時に成立させる設計は存在しない。

**ただし調査の副産物として、より確度の高い別案が見つかった**（後述「発見2」）。
そちらへの差し替えを推奨する。

---

## 発見1（最重要・緊急）: PA-API v5 は既に廃止済み

今アフィリエイトシステムを PA-API v5 前提で作っているなら、**その前提は3ヶ月前に消滅している。**

| 日付 | 出来事 |
|---|---|
| 2025-11-12 | アソシエイト・プログラムのポリシー改定（資格要件の厳格化） |
| 2026-01-31 | PA-API **Offers v1** 提供終了。S3 プロキシ経由のデータフィード/レポートも終了 |
| 2026-04-30 | PA-API v5 **非推奨化**（Amazon 公式アナウンス: "PA-API will be deprecated on April 30th, 2026. Please migrate to Creators API."） |
| **2026-05-15** | **PA-API v5 エンドポイント完全retire。SigV4 リクエストは全拒否** |

後継は **Creators API**。変更点は認証層が最も大きい。

- 認証: AWS Signature V4（Access Key ID / Secret Access Key）→ **OAuth 2.0**（Credential ID / Credential Secret）
- 資格情報の発行: アソシエイト・セントラル → ツール → Creators API から申請
- アプリケーションは最大2つまで作成可能

### アクセス資格（ここが最大の罠）

**直近30日間で10件以上の適格販売**が必要。しかもこれは**ローリング判定**で、
2月に11件あっても5月に4件なら**資格は失効する**。

適格販売の条件:
- 購入者がチェックアウトを完了していること
- 返品期間内に返品されていないこと
- 正しくタグ付けされたアソシエイトリンク経由であること
- デジタル商品（Kindle、Audible、音楽）およびサブスク登録もカウント対象

### レート制限

- 新規資格情報: **1 TPS / 8,640 リクエスト/日**（最初の30日間）
- 以降はアソシエイト売上に応じて自動的に上限が上がる

## 案3 が成立しない理由

### 障壁1: 24時間キャッシュ制限 — プロダクトのコアが規約で禁止されている

PA-API ライセンス契約では、取得したコンテンツの保持期間が **24時間**に制限されている
（画像リンクも同様。24時間経過後は直ちに API を再呼び出しして再取得・再表示する義務がある）。
長期保存が明示的に許されるのは ASIN 等の識別子のみ。

案3 の商品価値は **価格推移・ランキング変動の履歴**である。
つまり「履歴を蓄積すること」そのものが規約違反にあたる。

> これは回避策のある制約ではない。**売り物そのものが禁止事項**という構造なので、
> 設計を変えても解決しない。

### 障壁2: 第三者への提供禁止

ライセンスは、取得したコンテンツを**第三者の便益のためにダウンロード・複製・利用すること**、
および**データマイニング/ロボット等による収集**を禁止している。
取得コンテンツの改変・再販売・再配布も禁止対象。

案3 は「事業者にデータを売る」モデルであり、この条項に正面から抵触する。

### 障壁3: レート制限が2〜3桁足りない

```
初期上限:        8,640 リクエスト/日
日本の Amazon カタログ:  数千万 ASIN

仮に追跡対象を 10万 ASIN に絞っても:
  100,000 ÷ 8,640 ≒ 11.6 日 / 1巡
```

**1商品あたり11日に1回しか価格を見に行けない。**
せどり用途では価格更新は日次〜時間単位が要求されるので、機能要件を満たさない。
上限はアソシエイト売上に比例して上がるが、必要な桁に届くには相当な売上規模が前提になる。

### 障壁4: 事業基盤としての依存リスク

上記「10件/30日のローリング判定」により、**自分のアフィリ売上が落ちた月に API が止まる**。
API が止まればサービスが止まり、顧客が離れ、売上がさらに落ちる。
有料の B2B SaaS の基盤に置くには、この依存構造は許容できない。

### 補足: Keepa 等はなぜ成立しているのか

公式 API の制約下では上記の理由で不可能なので、**スクレイピングで実現されているとみられる**。
これは利用規約違反であり、法的リスクとアカウント停止リスクを伴う。
再現を目指す対象ではないと判断する。

### 正規ルートの代替: SP-API

「Amazon のデータで B2B ツールを作る」正規の道は **SP-API（Selling Partner API）**。
セラー本人が OAuth（Login with Amazon）で自分のデータへのアクセスを**自ら認可する**モデルなので、
第三者提供の問題が構造的に発生しない。

- 扱えるもの: 出品、注文、支払い、レポート、在庫、価格改定
- 要件: Amazon Services API Developer Agreement への同意、
  公開アプリは Seller Partner App Store への掲載が必要
- **注意**: サードパーティ開発者向けの SP-API 価格情報の提供終了に関するアナウンスがあり、
  価格系のスコープは着手前に現在の可否を確認する必要がある

→ 「せどり事業者向け」をやるなら SP-API ベースで、**顧客自身のセラーデータを扱うツール**として
設計し直す必要がある。これは案3 とは別物のプロダクトになる。

## 発見2: 移行難民という、今この瞬間に開いている市場

PA-API 廃止によって、**日本の Amazon アフィリエイト・ツール群が同時に機能停止・撤退している。**

| ツール | 状況 |
|---|---|
| **WPアソシエイトポスト** | **Creators API 対応を行わないと表明**。ツール自体を段階的に終了（廃止）予定 |
| **カエレバ** | リクエスト数が多く、現状のままではサービス継続不可 |
| Rinker / Pochipp | 移行対応に追われている |
| Cocoon | Creators API 移行の案内を出して対応中 |

同時に、**10件/30日の資格要件により、中小ブロガーの多くが API アクセス自体を失った。**

つまり今、以下が同時に発生している:

1. 定番ツールが next-1年で消える → 数万規模の乗り換え需要
2. 移行先の選択肢が薄い（対応済みプラグインが限られる）
3. 認証が OAuth 2.0 に変わり、非エンジニアには自力移行の難易度が上がった
4. 楽天メインへ切り替える動きが出ている（＝ Amazon 以外も束ねるツールに需要）

### この市場を取る場合の設計上の制約（重要）

**「API 代行/中継プロキシ」は作ってはいけない。**
自分の資格情報で取得したデータを他人に提供する形になり、障壁2（第三者提供禁止）に抵触する。

成立する形は1つだけ:

> **各ユーザーが自分の Creators API 資格情報で OAuth 認証して使うツール**を提供する。
> データは常にユーザー自身の資格で、ユーザー自身のサイトに表示される。
> こちらはソフトウェアを売るだけで、データには触れない。

この形なら障壁1〜4のすべてを回避できる（キャッシュ責務もユーザー側、レート制限もユーザーごと、
資格要件も自分の売上に依存しない）。**案3 と違い、規約と衝突しない構造が実在する。**

形態は WordPress プラグイン（買い切り or 年額）が本命。理由は前回述べた通りで、
既存マーケットプレイスに流通があり、個人開発最大の死因である集客を回避できるため。

### この案のリスク

- **タイミングが全て。** 移行需要は1〜2年で枯れる。既存プレイヤー（Rinker、Pochipp）が
  先に対応を完了させれば市場は閉じる。着手が遅れるほど価値が落ちる
- 10件/30日要件を満たせないユーザーは、そもそもどのツールでも救えない。
  **獲得可能な市場は「API 資格を持つアフィリエイター」に限定される**（想定より小さい可能性がある）
- Amazon の仕様変更に永続的に追随する保守コストを負う

---

## 推奨アクション

1. **【今週・最優先】自分のアフィリシステムの前提を確認する。**
   PA-API v5 ベースなら動いていないはず。Creators API（OAuth 2.0）への移行が先。
   ここが片付かないと他の案の土台がない
2. **【今週】アソシエイト・セントラルで自分の資格状況を確認する**
   （直近30日の適格販売が10件あるか）。ここが満たせないなら Amazon 依存の案は全て保留
3. **案3 は破棄。** SP-API ベースの別プロダクトとして再設計するか、やらないかの二択
4. **発見2 の移行需要を取りに行くかを判断する。** 判断期限は短い

- 調査時点で `webservices.amazon.com` / `affiliate.amazon.co.jp` /
  `affiliate-program.amazon.com` がネットワークポリシーによりブロックされており、
  **ライセンス契約の一次文書を直接読めていない。** 本レポートは条項を引用する二次情報に基づく

  維持されている可能性が高いが、着手前にアソシエイト・セントラルにログインして原文を確認すること
