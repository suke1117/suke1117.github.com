# 集客の設計

サイトを作っただけでは読まれません。ここでは流入をどう作るかを整理します。

**先に正直な現状**を書きます。実装済みは2つ、未実装が3つ、
そして**実装済みのうち1つは、いまの状態では効果が薄い**と考えています。

| 手段 | 状態 | 評価 |
| --- | --- | --- |
| 検索（SEO） | サイト側の基礎は実装済み | **主軸。この手法の本体** |
| Pinterest | 1記事3枚の画像を自動生成。投稿は手動 | **第2の主軸。相性が良い** |
| Threads | 自動投稿を実装済み（1日2回） | 立ち上げ期の相性は良い |
| Instagram | カルーセル8枚とキャプションを自動生成。投稿は手動 | 送客は弱いが、保存されると強い |
| X（旧Twitter） | 自動投稿を実装済み（1日4回） | **フォロワー0だと、ほぼ効果なし** |

投稿用の素材は、ビルドすると `/social/` にまとまります（noindex）。
画像のPNGとキャプションを、そこから取り出して投稿します。

---

## いちばん大事な前提：リンク先を自サイトに統一する

SNSにAmazonのアフィリエイトリンクを直接貼るのは、**やらない方針**にしています。
`data/x_templates.yml` の `link_target: "site"` がその設定です。

理由は3つ。

1. **Amazonアソシエイトは、リンクを掲載する媒体を申請時に登録する必要があります。**
   登録していないSNSアカウントでリンクを使うのは規約違反になり得ます。
   （運用を始める前に、必ず最新の規約と、自分のアカウント登録状況を確認してください）
2. **Meta系（Instagram / Threads）はアフィリエイトリンクの直貼りに厳しい傾向があります。**
   自サイトへのリンクなら、この問題が発生しません。
3. **計測ができます。** どのSNSから来た人が買ったのかが、サイト側で分かります。

SNSは「サイトに連れてくる」係、サイトは「比べて決める」係と役割を分けます。

## プラットフォーム別の性質

| | 外部リンク | フォロワー依存 | 蓄積性 | この手法との相性 |
| --- | --- | --- | --- | --- |
| **検索** | — | なし | **非常に高い** | ◎ 本体 |
| **Pinterest** | 投稿に直接貼れる | **低い**（検索エンジンに近い） | **高い**（ピンは消えない） | ◎ |
| **Threads** | 貼れる | 中 | 低い（流れる） | ○ |
| **Instagram** | **フィードに貼れない**（プロフィールとストーリーズのみ） | 高い | 中（保存される） | △ |
| **X** | 貼れるが伸びにくいとされる | **高い** | 低い | △ |

各サービスの仕様や規約は変わります。着手前に必ず最新の状況を確認してください。

### Pinterest を第2の主軸にする理由

Pinterest は**SNSというより検索エンジン**です。フォロワーがいなくても、
キーワードで検索した人にピンが表示されます。そして**ピンは消えずに蓄積します**。

「1度置いたものが、あとから何度も効く」という点で、この手法の考え方と同じ構造です。
比較表を画像にしたものは、まさにPinterestで検索される形式です。

`scripts/build_site.py` が記事ごとに `public/pin/<slug>.png`（1000x1500）を生成済みです。

### X の自動投稿について、正直な評価

**フォロワーが0の状態では、1日4回投稿しても、ほぼ誰にも届きません。**

いまの実装は「記事が増えたら自動で流れる」という仕組みとしては正しく動きますが、
**立ち上げ期の集客手段としては期待できません。**
止める必要はありません（コストはゼロなので）が、ここに時間を使うべきではありません。

Xが効いてくるのは、フォロワーが数千人規模になってからです。

### Instagram の使いどころ

Instagram は**フィード投稿から外部リンクに送客できません**。
プロフィールのリンクと、ストーリーズのリンクスタンプだけです。

なので「送客の手段」としては弱いです。ただし**保存される投稿**は別で、
比較表・チェックリスト・「買う前に測る場所」のような**あとで見返す情報**は保存されます。
保存数はアルゴリズム上も評価される要素とされています。

つまり Instagram は「送客」ではなく「認知と信頼の蓄積」に使います。

### Threads の使いどころ

外部リンクが貼れて、テキスト中心で、画像がなくても投稿が成立します。
**立ち上げ期にいちばん手数がかからない**のが利点です。

記事の一部（「レビューで多かった不満」1件だけ、など）をそのまま投稿して、
続きをサイトに置く形が作りやすいです。

## 順番

同時に全部やると、どれも中途半端になります。この順番を勧めます。

| 段階 | やること | 理由 |
| --- | --- | --- |
| **1. 記事30本まで** | **記事を書くことだけに集中する** | SNSに使う素材が、そもそも記事から生まれる |
| 2. Pinterest | 記事1本につき2〜3枚のピンを投稿 | フォロワー不要で、蓄積が効き始める |
| 3. Threads | 1日1〜2投稿。記事の断片を出す | 手数が最も少ない |
| 4. Instagram | 比較表を縦型カルーセルにして投稿 | 保存を狙う。送客は期待しない |
| 5. X | すでに自動で動いている | 追加の手間をかけない |

**段階1がいちばん重要です。** 記事が10本しかない状態でSNSを頑張っても、
連れてきた人に見せるものがありません。

検索で順位がつくまでには数か月かかるので、
その期間にPinterestとThreadsで細い流入を作っておく、という組み立てになります。

## ステマ規制について（全プラットフォーム共通）

アフィリエイトリンクを含むページへ誘導する投稿にも、**広告であることの明示が必要**です。

| 媒体 | 表示 | 状態 |
| --- | --- | --- |
| サイト | 全ページ上部に「本ページはプロモーションを含みます」 | 自動 |
| X | 文面に `#PR` | 自動 |
| Threads | 文面に `#PR`。末尾のタグではなく本文の一部として置く | 自動 |
| Pinterest | 画像のフッターに `#PR` | 自動（画像に焼き込み） |
| Instagram | 表紙に `#PR` バッジ、キャプションの**1行目**に明示 | 自動 |

キャプションの1行目に置いているのは意図的です。
末尾のハッシュタグの山に紛れさせると、明瞭性を欠くと判断される可能性があります。

## 生成される素材

`python scripts/build_site.py` を実行すると、比較記事1本につき次が作られます。

| 素材 | 枚数 | 出力先 |
| --- | --- | --- |
| Pinterest：比較表 / 選ぶ基準 / よくある失敗 | 3 | `public/pin/<slug>*.png` |
| Instagram：カルーセル（表紙・基準3・比較表・失敗・まとめ・導線） | 8 | `public/ig/<slug>-N.png` |
| Instagram：キャプション | 1 | `/social/` ページ内 |

PNGへの変換には `rsvg-convert` が必要です。GitHub Actions では自動で入ります。
手元では SVG のみが生成されます（`sudo apt install librsvg2-bin` で変換できます）。

投稿文は次で確認できます。

```bash
python scripts/post_to_threads.py --dry-run
python scripts/post_to_x.py --dry-run
```

## 流入の計測

SNS経由のリンクには utm パラメータが自動で付きます。

```
?utm_source=threads&utm_medium=social&utm_campaign=<記事のslug>
```

`utm_source` は `x` / `threads` / `pinterest` が入ります。
Pinterest はピンを手動で貼るため、`/social/` ページに貼るべきURLを表示しています。
`data/site.yml` の `utm: false` で無効化できます。

## 認証情報

| Secret | 用途 |
| --- | --- |
| `X_API_KEY` / `X_API_SECRET` / `X_ACCESS_TOKEN` / `X_ACCESS_TOKEN_SECRET` | X への投稿 |
| `THREADS_USER_ID` / `THREADS_ACCESS_TOKEN` | Threads への投稿 |

Threads のアクセストークンは**60日で失効します**。
失効すると投稿が止まるので、更新の予定を入れておいてください。
未設定の場合、ワークフローは dry-run になるだけで失敗はしません。
