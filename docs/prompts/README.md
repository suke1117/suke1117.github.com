# プロンプト集

記事を作る手順は4STEPです。
Claude に投げて、返ってきた YAML を `data/` に貼る、という流れに統一してあります。

| STEP | プロンプト | 出力先 |
| --- | --- | --- |
| 1. ジャンル選定 | [01-genre-research.md](01-genre-research.md) | 検討メモ（リポジトリには入れない） |
| 2. 比較記事の生成 | [02-comparison-article.md](02-comparison-article.md) | `data/products.yml` と `data/comparisons.yml` |
| 3. リンク位置 | プロンプト不要 | テンプレート側で固定済み（[下記](#step3-リンクの位置)） |
| 4. 回遊の設計 | [03-related-articles.md](03-related-articles.md) | `data/comparisons.yml` の `related` |

貼り付けたあとは必ず:

```bash
python scripts/validate.py     # 型と表現のチェック
python scripts/build_site.py   # 生成
```

## STEP3: リンクの位置

STEP3 だけプロンプトがありません。リンクの位置は記事ごとに考えるものではなく、
**テンプレート（`templates/comparison.html`）で固定してある**ためです。

| セクション | リンク | 理由 |
| --- | --- | --- |
| 3. 選ぶ基準 | **置かない** | 読者はまだ選び終わっていない。ここで押すと比較表を見る前に離脱する |
| 5. 商品ごとの解説（各末尾） | 1つずつ置く | 向いている人／向いていない人を読んだ直後がいちばん判断が固まっている |
| 7. 状況別のおすすめ | 再掲する | ここまで読んだ人は比べ終わって疲れている。3行でまとめると決まる |

記事を書くときにリンクの位置を考える必要はありません。
`comparisons.yml` に構造化データを入れれば、その位置に自動で入ります。

## 実際に使った一言（own_note）だけは自分で書く

`scripts/validate.py` は、比較記事に載っている商品の `own_note` が空か雛形のままだと
**エラーで公開を止めます**。

生成された本文をそのまま出すと、読者にも検索エンジンにも見抜かれます。
1商品につき1〜3行でいいので、実際に使って気づいたことを足してください。

使ったことがない商品について実感を書くのは、単純に嘘になるので絶対にやめてください。
その商品は比較記事に入れず、`no_post: true` を付けて候補から外します。
